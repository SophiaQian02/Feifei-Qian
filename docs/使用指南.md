## 3. 修改或添加论文

打开 `_pages/about.md`。已有三篇论文沿用模板原本的「左图、右文、会议角标」布局。

- 标题：修改卡片中的粗体文字或 Markdown 链接。
- 作者：修改作者行，自己的姓名使用 `**Feifei Qian**` 加粗。
- 会议和类型：修改 `<div class="badge">…</div>`。
- 论文链接：修改 `[**Paper**](...)` 或标题链接。
- 配图：把图片放进 `images/papers/`，修改对应 `img` 的文件名和 `alt` 描述。
- 一句话简介：修改卡片内的 `- ...` 列表内容。

添加新卡片时，复制完整的下列区块，并保留 `markdown="1"` 和空行：

```html
<div class='paper-box'><div class='paper-box-image'><div><div class="badge">Conference 2027</div><img src='{{ "/images/papers/my-paper.png" | relative_url }}' alt="Overview of my method" width="100%"></div></div>
<div class='paper-box-text' markdown="1">

[**Paper title**](https://example.com/paper)

**Feifei Qian**, Coauthor A, Coauthor B

[**Paper**](https://example.com/paper) / [**Code**](https://github.com/username/repository)
- One sentence about the contribution.
</div></div>
```

没有配图时，直接添加列表条目即可：

```markdown
- [**Paper title**](https://example.com/paper). **Feifei Qian**, Coauthor. **Conference 2027**.
```

示例地址必须换成真实链接，没有链接就只写标题，不要放一个不能打开的按钮。当前三张配图是依据研究描述绘制的概念示意图，不是论文中的实验结果图；可以随时换成自己的方法图。

NeurIPS 2026 Spotlight 与 ICLR 2027 在投状态来自你提供的简历。ICLR 稿件单列于 Under Review；后续录用后可移动到正式论文区。FCS 使用“online in 2026”是为了区分在线发表时间与 2027 年卷期。

## 4. 添加技术博客

在 `_posts/` 创建文件，比如 `2026-10-09-llm-evaluation.md`：

```markdown
---
layout: default
title: "LLM Evaluation Notes"
permalink: /blog/llm-evaluation/
date: 2026-10-09
lang: en
tags: [LLM, Evaluation]
excerpt: "A short summary of this note."
author_profile: true
---

# {{ page.title }}

This is my introduction.

## Background

Write the article here.

## References

- [Reference title](https://example.com)
```

保存后，博客索引会自动按时间倒序显示，不需要手动在 `_pages/blog.md` 中添加条目。

- 中文文章将 `lang` 设为 `zh-CN`。
- `permalink` 是文章的固定网址。文章发布后尽量不要改，避免旧链接失效。
- 文章日期不要设成未来日期，否则 Jekyll 默认不会显示。
- 新文章如需出现在首页，再去 `_pages/about.md` 的 Technical Notes 下添加推荐链接。
- 文章含公式时，在顶部配置增加 `mathjax: true`；公式会使用模板原有的 MathJax CDN。

GraphRAG 是从原仓库保留的 HTML 正文，所以文件扩展名为 `.html`；新文章可以直接写更方便的 Markdown。它的旧路径 `/2026/04/08/graph-rag/` 在当前站点内会跳转到 `/blog/graphrag/`。这不会更改旧仓库或旧网站上的内容。

## 5. 修改顶部导航

打开 `_data/navigation.yml`，例如：

```yaml
main:
  - title: "About Me"
    url: "/#about-me"
  - title: "Publications"
    url: "/#publications"
  - title: "Blog"
    url: "/blog/"
```

顺序就是显示顺序。首页每个区块有固定锚点，例如：

```html
<span class='anchor' id='publications'></span>
```

`/#publications` 必须与 `id='publications'` 一致。只改可见标题不影响跳转；如果改 `id`，同步更新导航。新增 News 导航可以使用 `url: "/#news"`。

所有站内链接都应使用 `relative_url`，例如：

```liquid
{{ '/blog/' | relative_url }}
{{ '/images/portrait-web.jpg' | relative_url }}
```

这样同一套文件可以正确处理项目站点路径，而不会跳到另一个仓库的网站。

## 6. 本地预览

需要 Ruby、Bundler，以及本地预览清单 `Gemfile.preview` 中的依赖。当前机器使用 Homebrew Ruby 时，先设置 PATH：

```sh
export PATH="/opt/homebrew/opt/ruby/bin:$PATH"
cd /Users/qianfeifei/Sophia_Qian.github.io
BUNDLE_GEMFILE=Gemfile.preview bundle install
./run_server.sh
```

浏览器打开：

```text
http://127.0.0.1:8766/
```

修改 Markdown 后服务通常会自动重新生成。修改 `_config.yml` 后，请按 `Ctrl+C` 停止服务，再运行 `./run_server.sh`。

只检查是否能构建，不启动服务：

```sh
BUNDLE_GEMFILE=Gemfile.preview bundle exec jekyll build
```

本地预览使用精简依赖文件 `Gemfile.preview`；原 `Gemfile` 保留用于 GitHub Pages。无需修改原模板的视觉样式。

本地 8765 端口如果仍打开，是上一版设计的预览；本模板使用 **8766**，请看新地址。
